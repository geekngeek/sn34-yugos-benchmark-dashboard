How benchmark scores work

The dashboard has data from 19 sources. They do not all count points the same way. There are six kinds of score. This page explains each one with a picture and a real example from the dashboard.

The one big rule: compare scores only inside the same benchmark.

A score is like a measurement with a ruler. Different benchmarks use different rulers. "80" on one ruler and "1500" on another ruler do not mean the same thing, so you cannot put them side by side.

Kind 1 · Higher is better · 0–100%

Right or wrong

Humanity's Last Exam, MMLU-Pro, GPQA, MMLU, SimpleQA (OpenAI), SimpleQA Verified and FrontierMath (Epoch AI), AIME (MathArena)

This is the simplest kind. The model answers many questions. Each answer is right or wrong. The score is the percent of right answers. This percent is also called accuracy.

Real example

On MMLU-Pro, Gemini 3.1 Pro scores 91.2%. It answered about 91 of every 100 questions correctly.

On Humanity's Last Exam, the best model (Gemini 3 Pro) scores only 38.3%. This test is very hard.

Good to know
  • Guessing gives free points. MMLU-Pro has 10 choices per question, so random guessing already gets about 10%. GPQA has 4 choices, so guessing gets about 25%. A 39% on GPQA is only a little better than luck.
  • Some tests repeat each question. MathArena asks every AIME problem 2–4 times and averages. Epoch AI shows a small "±" error (FrontierMath: 95.1% ± 1.3). Two scores closer than this are basically tied.
  • The "Accuracy" column in the dashboard is filled only for this kind. Here it is the same number as the score.
Kind 2 · Higher is better · 0–100%

Finished the job

SWE-bench, SWE-bench Pro, Terminal-Bench, Aider Polyglot, τ²-bench, HumanEval

Here the model does real work, like fixing a bug in a big program. Nobody checks the answer by hand. Instead, hidden tests run. If all tests pass, the task counts as done. The score is the percent of tasks done.

Real example

On SWE-bench Verified, Claude 4.5 Opus scores 79.2%: about 396 of the 500 bugs were fixed.

The benchmarks in this group differ in small rules. These rules change the number:

The rules of each benchmark
  • SWE-bench / SWE-bench Pro: fix a real bug in a real project. One try.
  • Terminal-Bench: work in a Linux terminal. Every task runs 5 times, so the score is an average with a "±" (Fusion: 71.2% ± 2.9).
  • Aider Polyglot: coding exercises in 6 languages. The model gets a second try after seeing the test errors.
  • τ²-bench: act as a customer-service agent in a whole conversation. The task counts only if the full conversation ends correctly (Claude Sonnet 4.5, Retail: 86.2%).
  • HumanEval: write one short Python function. "pass@1" means the first answer must pass.
Kind 3 · Higher is better · 0–100

Partial points

LiveBench categories, OCRBench v2, RULER

Some tasks are not simply right or wrong. A task can be half done. Then the task earns part of its points. The score is the average of all the task points, shown from 0 to 100.

Real example

In LiveBench 2.0, Gemini 4 Neon scores 95.6 in Browser and 81.5 in Design. Each category is the average task score of that category.

OCRBench v2 averages 8 reading skills (text recognition, math in images, and more). RULER scores long texts at 4K to 128K words-pieces (tokens) and averages them.

Good to know

A "69" here does not mean "69% of tasks were done". It means "on average, 69% of the points were earned". Partial credit makes these scores a bit higher than pass-or-fail scores would be.

Kind 4 · Higher is better · index points

Mix of many tests

Artificial Analysis Intelligence Index and its 6 capability indexes, BenchLM Overall and categories, LiveBench Overall

Some sites combine many benchmarks into one number. This is called an index. It is easy to read, but it hides the details. Some parts can count more than others. This is called weighting.

Real examples

Artificial Analysis Intelligence Index: Claude Fable 5.2 scores 64.8. This is not a percent. It is points on the index scale (version 5). Compare it only with other version-5 scores.

BenchLM Overall: Claude Fable 5.2 scores 93.3, with a likely range of 88.5–98.0. BenchLM gives a range because not every model has results on every benchmark.

Kind 5 · Higher is better · rating, about 1000–1800

Head-to-head votes

LMArena (Text, WebDev, Vision, Agent, Document, Search), WildBench WB-Elo

A person asks a question. Two hidden models answer. The person picks the better answer. After many thousands of votes, each model gets a rating, like a chess rating. There is no top score; only the gap between two ratings matters.

What the gap means

Gemini 4 Carbon (1539) is 11 points above Gemini 4 Argon (1528). That means people prefer Carbon's answer only about 52% of the time. They are almost equal.

A 100-point gap means the higher model wins about 64% of the votes. A 400-point gap means about 91%.

Good to know

Ratings come from people's taste: style, length and friendliness matter too, not only correctness. Each arena (Text, WebDev, Vision…) has its own ratings, so do not compare a Text rating with a WebDev rating.

Kind 6 · Higher is better · −80 to 100

Judge's checklist

WildBench WB-Score

Real user questions are answered by the model. An AI judge (GPT-4o) checks each answer against a checklist and gives a grade from 1 to 10. Then WildBench shifts the scale so that an "OK" grade of 5 becomes 0:

WB-Score = (average grade − 5) × 20

Real example

Athene-70B scores 59.4: its average grade was about 8 out of 10. Gemma 2B IT scores −5.3: its average grade was a little under 5.

WildBench data is from 2024, so newer models are not in it.

Watch out: a few scores are "lower is better"

A few BenchLM benchmarks measure mistakes, for example a hallucination rate (how often the model makes things up) or a word error rate. For these, a small number is good. The dashboard always sorts highest first, so read these the other way round.

Three tips for reading the dashboard
  • Pick one benchmark in the Source / Benchmark filter before you compare models.
  • Small gaps can be noise. Look for a "±" or a range before you call one model better.
  • Check the Effort column. The same model can score very differently at "low" and "max" effort.
